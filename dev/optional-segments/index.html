Optional sequence wildcards — support analysis

MatchPy's Optional(wildcard, default) wraps any wildcard; ours supports optional slots only (optional(x) → VarSpec.Slot with a default). The MatchPy one-to-one port (test/matchpy/one_to_one.jl) therefore skips the optional-sequence cases (oa__/oa___, and oa_ cases where the subject leaves ≥2 args for an optional dot under A/AC).

Capture-wise, an optional sequence is a min = 0 segment. The two deltas:

  1. Empty capture binds default, not the empty run/identity — which is also why MatchPy allows oa__ under heads with no identity (f(oa__) vs f() → o ↦ a). VarSpec.Segment currently has no default field and optional(x) is slot-kind, so the spec/marker layer needs extending regardless.
  2. oa_ under A/AC absorbs multi-arg leftovers — MatchPy's dot is a sequence matcher under associative heads: it takes all leftover args and materializes 1 → bare element, ≥2 → head(...), 0 → default. Our slot optional consumes at most one arg.

Notes

  • Ordering. MatchPy tries the consume-alternative before the default and dispatches optional positions before sequence positions — matching our optionals-then-segments phase order, so enumeration order is preserved.
  • Perf summary. Everything optional-segment-related is marginal cost on top of the existing min = 0 machinery — the enumeration space is already generated; the deltas are a spec field, a bind-default branch, and materialization. Under AC an optional sequence would dispatch in the segment phase (sub-multiset enumeration), which is already the dominant combinatorial cost.
  • Design question. The empty-capture binding representation: extra = default vs empty-run + a default-aware _seg_value. This decides how non-linear rechecks compare a defaulted occurrence against a captured run — see the ambiguous-materialization item in TODO.md for the related recheck question.
